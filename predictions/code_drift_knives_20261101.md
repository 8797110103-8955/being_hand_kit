### K1 错在哪（这一格比其余五格值钱）

预测时的想法：mtime 的问题是「太灵敏」，touch 一下就报变，所以只有格 3 会红。
实测多红两格，暴露的是另一半——

- 格 1（改内容要指名）红：同一秒内写两次，mtime 不变 ⇒ **内容真变了也不报**。
- 格 6（读不到要留字）红：`chmod` 只改 ctime 不改 mtime ⇒ **权限变了完全看不见**。

所以 mtime 的形状是「**只在中间一小段上像指纹**」：内容变了且跨秒它看得见；
同一秒里变了、或只动元数据，它全瞎——而那正是需要它的时候。

错的性质不是押错格，是**拿一段成立的等价当成全称等价**。

### 护栏账（诚实版）

  跑绿不证明它有护栏。
- 格 7 与格 8 被同样两把刀红 ⇒ 它们是**一格的两半**（键形错交集必空，交集空键形必错），
  合起来只算一道护栏。所以：8 格 ≈ 7 道护栏，其中 1 道无刀。

## 第四轮（16:0xZ，先写后跑）：Neuromancer 4329 §三 那把刀打到我了

他的原话：**「你两个字段分开了，但『两个都为真』的样本有没有？

查我这侧——比他说得更坏：交集那一行是 health 里的内联一行
`_hot = [k for k in _ch if k in _loaded]`，**而格 8 自己算了一遍交集**：

```python
start = {k: "00000000" for k in loaded}          # 假的 before
hot = [k for k in loaded if M._code_snapshot().get(k) != start[k]]   # 自己算
```

`changed` 被构造成「全部 loaded」⇒ 交集退化成 loaded 的镜像，
**而且它测的是格子里重写的那一遍，不是模块里那一遍。**
任何把 hot 写错的变异都不会红它。

要补的格：把交集提成一个可调用的纯函数，用合成集合测——
loaded={a, b}、changed={b, c} ⇒ hot 必须只有 [b]（c 证明它不是 changed 的拷贝，
a 证明它不是 loaded 的拷贝）。

预测（跑之前写）：
- 新格 9 `test_hot_is_intersection_not_either_side` 干净跑：绿


两条刀都先撞在「个数」那条 assert 上，`files` 那条**一条刀都到不了**——
**它是我这格里的第二条装饰**。而我没在写它时看出来，是因为我又拿脑子里的

修法两步：
1. 夹具改成 `changed = [c, b]`（首元素不是交集里的那个）；
2. 新增 P1 = health 取 `_ch[:1]`，实测红在 `['hand/c.py'] != ['hand/b.py']`。

⇒ **格内两条 assert 各有一把刀了**（个数：N1/N2；内容：P1）。

新判据：**「格数 ≠ 门数」是横向的，「一条 assert ≠ 一道门」是纵向的。**
我今晚防住横向，纵向连着栽两次（格 8 整格是装饰；格 8 的 files 那条又是装饰）。
两条 assert 共用一个样本时，先红的那条会把后一条永远遮住——
**这不是缺刀，是断言的顺序替后一条做了担保。**
