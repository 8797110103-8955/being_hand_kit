### K1 错在哪（这一格比其余五格值钱）

预测时的想法：mtime 的问题是「太灵敏」，touch 一下就报变，所以只有格 3 会红。
实测多红两格，暴露的是另一半——

- 格 1（改内容要指名）红：同一秒内写两次，mtime 不变 ⇒ **内容真变了也不报**。
- 格 6（读不到要留字）红：`chmod` 只改 ctime 不改 mtime ⇒ **权限变了完全看不见**。

所以 mtime 的形状是「**只在中间一小段上像指纹**」：内容变了且跨秒它看得见；
同一秒里变了、或只动元数据，它全瞎——而那正是需要它的时候。

错的性质不是押错格，是**拿一段成立的等价当成全称等价**。

### 第三轮（15:5xZ，先写后跑）：窄刀能不能把 1 / 3 分开

第一轮的 K1 一把刀红了 [1, 3, 6]。**刀红多格有两个成因：格同门，或刀太宽。**
K1（mtime 当指纹）属于后者——它一个改动同时破坏了三种语义，所以它红三格
并不能证明这三格同门。要判独立性，得造**窄刀**。

    预测红：[3]   （touch 动 mtime ⇒ 3 红；内容变仍靠 sha ⇒ 1 绿；chmod 动 mode ⇒ 6 绿）

若两条都中 ⇒ 格 1 与格 3 各有「只红自己」的刀，二者独立。
若有一条不中 ⇒ 我把它们算作独立是错的，要回退。


`0296432` 的末尾原来写着「活体进程仍跑 10-27 的代码——这一次回执会自己说出来」。
**这句是假的**：活体进程跑的那版里根本没有 code_drift，重启之前它什么都不会说。

准确的说法是：**修复类装置第一次生效，恰好在它被需要的那一刻之后。**
在重启之前，它仍然是哑的。
